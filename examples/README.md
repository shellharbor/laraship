# Примеры для deploy-laravel.sh

Готовые сценарии запуска `deploy-laravel.sh`. Каждый скрипт состоит из шапки-комментария (сценарий, результат, что поменять перед запуском) и одной команды развёртывания. Подробности по флагам — в [../README-ru.md](../README-ru.md).

| Файл | Сценарий | Ключевые флаги |
|---|---|---|
| [01-minimal-postgres.sh](01-minimal-postgres.sh) | Минимальный запуск: slug, порты и пароли генерируются, домен получает префикс-slug | `--domain` `--db-type postgres` `--ssl-email` |
| [02-mysql-explicit-slug.sh](02-mysql-explicit-slug.sh) | MySQL в контейнере, явные slug и домен | `--slug` `--db-type mysql` |
| [03-explicit-db-credentials-and-ports.sh](03-explicit-db-credentials-and-ports.sh) | Заданные имя, пользователь и пароль БД, пароль Redis и все порты хоста | `--db-postgres-*` `--redis-password` `--port-http/https/php/redis/postgres` |
| [04-native-postgres.sh](04-native-postgres.sh) | Системный PostgreSQL на хосте вместо контейнера | `--db-native` `--db-type postgres` |
| [05-native-mysql.sh](05-native-mysql.sh) | Системная MySQL на хосте | `--db-native` `--db-type mysql` `--db-root-password` `--port-mysql` |
| [06-filament-autogenerated.sh](06-filament-autogenerated.sh) | Filament, имя и пароль администратора генерируются | `--install-filament` `--filament-email` |
| [07-filament-explicit-credentials.sh](07-filament-explicit-credentials.sh) | Filament с заданными данными администратора, MySQL | `--install-filament` `--filament-email` `--filament-name` `--filament-password` |
| [08-basic-auth.sh](08-basic-auth.sh) | Закрытый стенд с HTTP Basic Auth | `--enable-basic-auth` `--auth-user` `--auth-password` |
| [09-no-ssl.sh](09-no-ssl.sh) | Без сертификата (DNS ещё не готов); внутри описано ручное получение SSL | `--no-ssl` |
| [10-production-full.sh](10-production-full.sh) | Production: всё явно, Filament, отправка данных на endpoint, архив | `--laravel-version` `--install-filament` `--endpoint` `--create-backup` |

Вспомогательные файлы:

| Файл | Что это |
|---|---|
| [project.env.example](project.env.example) | Пример `/var/www/<slug>/.env`, который генерирует скрипт: PostgreSQL + Basic Auth + Filament, значения фейковые |
| [endpoint-payload.json](endpoint-payload.json) | Пример тела PUT-запроса, которое скрипт отправляет на `--endpoint` |

## Как пользоваться

Скрипты выполняются **на сервере**, а не на локальной машине. Папка `examples/` приезжает на сервер вместе со всей папкой `laravel-deploy` (например, в `/opt/laravel-deploy/`). Каждый пример по умолчанию вызывает `deploy-laravel.sh` из **своей** папки `laravel-deploy` (`DEPLOY_DIR` = родительская папка `examples/`), поэтому его можно запускать с места из любого каталога:

```bash
ssh user@server

# 1. отредактировать домен, email, пароли прямо в копии на сервере
sudo nano /opt/laravel-deploy/examples/02-mysql-explicit-slug.sh

# 2. запустить
bash /opt/laravel-deploy/examples/02-mysql-explicit-slug.sh
```

Если пример скопирован за пределы `laravel-deploy/` (например, в `~/`), укажите папку со скриптом явно: `DEPLOY_DIR=/opt/laravel-deploy bash ~/02-mysql-explicit-slug.sh`.

Перед запуском учтите:
- `example.com`, `admin@example.com` и пароли `ChangeMe_...` — заглушки, замените их.
- Если папка `/var/www/<slug>` уже есть, скрипт **удалит её** и развернёт проект заново (см. «Повторный запуск» в [../README-ru.md](../README-ru.md)).
- В явных паролях используйте только символы `A-Za-z0-9@%_+-`.
